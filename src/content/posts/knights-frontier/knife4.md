# IDS (침입 탐지 시스템)
보안 관리자에게 알려진/잠재적 위협을 경고하거나 중앙 집중식 보안 도구로 경고를 보내, 네트워크 위협 탐지의 가속화/자동화에 도움을 준다. 

# 동작 원리
### Misuse detection (오용 탐지 기법)
Signature detection(시그니처 기반 탐지)이라고도 불린다.  
새 공격의 분석이 끝나면 공격의 특징(패턴)을 추출하고 DB에 특징을 저장한다. 패턴과의 비교로 공격인지 판단한다.  
특정 멀웨어 변종에서 나타나는 일련의 코드가 대표적인 공격 시그니처 예시이다. 

이미 알려진 공격은 놓치지 않으나, New Attack(새 패턴)은 못잡아낸다.  
때문에 효과적 탐지를 위해서는 새 공격이 등장하고 기존 공격이 진화함에 따라 시그니처 DB가 정기적으로 업데이트 되어야 한다. 

### Anomaly detection (이상 탐지 기법)
정상 행위에 대한 모델(기준선)을 만든 후, 바운더리를 벗어날 경우 공격으로 간주한다.  
보통보다 많은 대역폭을 사용하는 프로세스나, 일반적으로 닫혀있는 포스를 여는 디바이스와 같은 경우이다.  
모델을 만들 때는 규칙 기반, 머신러닝, 통계적 방법을 사용한다. 

시그니처 기반 탐지보다는 새 공격(제로데이)를 잘 탐지할 수 있다. 
정상 행위에 대한 모델이 완벽하지 않기(바운더리 넘어가는 사람이 존재) 때문에 정상이지만, 공격으로 간주하는 False Positive(오탐)가 크다. 

### 평판 기반 탐지
악의적이거나 의심스러운 활동과 관련된 IP주소 및 도메인의 트래픽을 차단한다. 

### 상태 기반 프로토콜 분석
프로토콜 동작에 중점. 단일 IP 주소가 단기간에 여러 개의 TCP 연결을 동시에 요청하는 것을 감지하여 서비스 거부(DoS) 공격을 식별할 수 있다. 

## 유형 
### HIDS(호스트 침입 탐지 시스템)
호스트(노드) 기반 침입 탐지 시스템이다. 
N1, N2, N3, N4 ... 각각의 HIDS 소프트웨어가 돌아간다 (각 머신(엔드포인트)에 부가적으로 SW를 설치).  
노드로 날아오거나, 노드에서 나가는 데이터를 수집힌다. 어떤 사용자가 접근을 시도했는지, 어떤 작업을 했는지 기록으로 남기고 추적한다. 해당 디바이스 활동만 모니터링하는 것이다.  

HIDS는 일반적으로 중요한 운영체제 파일의 스냅샷을 주기적으로 생성하고, 시간 경과에 따라 스냅샷을 비교하는 방식으로 작동한다. 로그 파일 편집이나 구성 변경과 같은 변경 사항을 발견하면 보안 팀에 알린다. 

이는 다른 침입 탐지 시스템보다 비용이 높고, 자신이 공격 대상이 되는 경우에만 침입 탐지가 가능하다(전체 네트워크에 대한 침입 탐지는 못함).  
결국 SW이기에 공격자의 타깃이 될 수 있다(운영체제의 취약점이 HIDS를 손상시킬 수 있음).

### NIDS(네트워크 침입 탐지 시스템)
네트워크 기반 침입 탐지 시스템이다.  
여러개의 노드를 연결하는 라우터나 스위치. 왔다갔다(인바운드&아웃바운드 트래픽) 하는 트래픽을 모두 보고 수집할 수 있는 시스템으로 여러 노드 사이의 관계성을 볼 수 있다(네트워크 전반의 디바이스에 대한 감시).  
네트워크에서 하나의 독립된 시스템으로 운용되고, 보통 라우터나 스위치 바깥에 붙어 운용된다(내부에서 운용하기에는 부하가 큼).
> 스위치 환경에서 NIDS를 설치하려면 다른 부가 장비를 필요로 한다. 

보통 네트워크의 경계의 방화벽 바로 다음에 배치된다.  
내부자 위협이나 사용자 계정을 가로챈 공격자를 잡기 위해 네트워크 내부에 배치될 수도 있다. 예를 들어 서브넷 간 흐르는 트래픽을 모니터링하기 위해 분할된 네트워크의 각 내부 방화벽 뒤에 배치될 수 있다. 

합법적인 트래픽의 흐름을 방해하지 않기 위해 대역 외에 배치되며, 트래픽이 직접 통과하지 않는다. NIDS 패킷 자체가 아닌 네트워크 패킷의 복사본(Out-Of-Band)을 분석하는 것이다(IP를 소유하지 않음).  
이렇게 하면 합법적인 트래픽은 분석을 기다릴 필요가 없지만 NIDS는 여전히 악성 트래픽을 포착하고 플래그를 지정할 수 있습니다. 

### PIDS(프로토콜 기반)
서버와 디바이스 간의 연결 프로토콜을 모니터링한다. 보통 HTTP 또는 HTTPS 연결을 모니터링하기 위해 웹서버에 배치된다.

### APIDS(애플리케이션 프로토콜 기반 IDS)
애플리케이션 계층에서 작동해서 애플리케이션별 프로토콜을 모니터링한다. SQL 인젝션을 탐지하기 위해 웹서버와 SQL DB 사이에 배치되는 경우가 많다. 

# IPS (침입 방지 시스템)
Intrucsion Protection System. 탐지하고 나서 실시간 대응까지 해주는 친구이다. (IDS와의 차이)

## 동작 원리
방화벽은 IP주소나 포트를 기반으로 네트워크 공격을 차단할 수 있으나, 응용 프로그램 수준의 공격과 새로운 패턴의 공격에 대한 적응력이 매우 낮고, 실시간 대응 또한 불가능하다. 즉, 세밀한 대응이 불가능하다. 

Sandbox 형태의 가상 머신에서 패킷을 한 번 돌려보고 징후를 확인하는 방식으로 동작한다. 
### 시그니처 기반 탐지
### 이상 징후 기반 탐지
### 평판 기반 탐지
### 상태 기반 프로토콜 본석 
위의 4가지는 IDS의 동작원리 부분의 내용과 동일하다. 대신 IPS는 해당 탐지에 대해 조치를 취한다(IP주소 차단 등...)
### 정책 기반 탐지
설정한 보안 정책을 기반으로 동작하고, 보안 정책을 위반하는 행위를 탐지할 때마다 해당 시도를 차단한다.  
예를 들어 호스트에 액세스할 수 있는 사용자 및 장치를 지정하는 액세스 제어 정책을 설정했을 때, 승인되지 않는 사용자가 호스트에 연결을 시도하면 IPS가 이를 중지한다. 

## 유형
### NIPS(네트워크 기반 침입 방지 시스템)
NIDS와 내용 동일
### HIPS(호스트 기반 침입 방지 시스템)
HIDS와 내용 동일. 단, 직접 조치해주어야 하기 때문에 실제 트래픽이 지나가는 길목(in-line)에 있어야 한다.
### NBA(네트워크 행동 분석)
네트워크 트래픽 흐름을 모니터링한다. 대부분의 NBA는 소스 및 대상 IP주소, 사용된 포트, 전송된 패킷 수 등 통신 세션에 대한 상위 수준의 세부 정보에 중점을 둔다. (다른 IPS처럼 패킷 검사도 가능)
### WIPS(무선 침입 방지 시스템)
무선 네트워크 프로토콜을 모니터링하여 회사의 WiFi에 액세스하는 승인되지 않은 사용자 및 장치와 같은 의심스러운 활동이 있는지 확인한다. 무선 네트워크에서 알 수 없는 개체를 감지하면 연결을 종료시킬 수 있으며, 잘못 구성되거나 보안되지 않은 장치를 탐지하고 중간자 공격(MITM, 공격자가 사용자의 통신을 몰래 감시)을 차단하는데 도움이 될 수 있다. 


## 장단점 및 차이점
### IDS
- 장점: 
    - 스위치나 라우터를 목적지로 공격하는 경우는 드물음 -> HIDS에 대해 공격 당할 확률 낮음
    - IP를 소유하지 않음 -> 직접적인 공격은 거의 완벽하게 방어가 가능
    - 존재 사실을 숨길 수 있음
    - 장비에 장애가 발생하거나 오탐이 나도 기존 네트워크 흐름에 영향 주지 않음

- 단점:
    - IPS와 다르게 실시간 조치 불가 (수동적 대응)
    - 대용량 트래픽 발생 시 미러링 과정에서 패킷 유실이 발생해 False Negative(미탐) 가능

### IPS
- 장점: 
    - 탐지에 조치까지 취해줌
    - In-line 설치로 악성 트래픽이 내부망에 도달하기 전 실시간으로 차단 가능

- 단점: 
    - False Positive(오탐): 오탐 시 정상 트래픽까지 차단하여 가용성 저하 가능
    - 패킷을 직접 통과시키면서 검사하므로 네트워크 병목 및 지연 발생
    - 장비 자체에 장애가 발생하면 네트워크 전체가 단절 가능 (SPOF, Single Point Of Failure)

### 차이점
| 구분 | IDS | IPS |
| 목적 | 탐지 및 알림 | 탐지 및 알림 + 조치 | 
| 구성 방식 | Out-of-band(복사본으로 검사) | In-line(트래픽 경로상 직접 위치) |
| 네트워크 영향 | 장애/오탐 시 서비스에 영향X | 장애/오탐 시 서비스 단절 또는 속도 저하 |
| 은닉성 | 외부 노출X(IP없음) | 네트워크 경로에 노출되어 장비에 대한 공격 위험 존재 |
